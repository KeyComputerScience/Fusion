HARTH is the preferred untouched collection for the next physical verification. The [official UCI metadata](https://archive.ics.uci.edu/dataset/779/harth) documents 22 participants, back/thigh AX3 accelerometers at 50 Hz, approximately two hours per participant, and a 296.4 MB download. A fixed stride of 50 yields approximately 129,000 retained rows. Numeric subject-ID ranks define 8 fit, 4 calibration and 10 test participants. These are metadata estimates; no HARTH raw data were downloaded, opened or evaluated.

`adapter.py` implements simultaneous physical-source grouping, same-row timestamps, raw-row provenance, separate participant histories, and chronological prefix fitting. Ordinary one-second retained-interval jitter does not reset histories. A full acquisition-row timestamp gap above one second does. Actual participant/history-run counts must be reported, and the aggregate loss guarantee is −B times the actual test run count, because each run receives its own budget.

The planned 1 Hz snapshots use direct subsampling without an anti-alias filter. Each source model receives its own xyz coordinates and two past retained rows; the reference receives both sensors. Source fitting and normalization use the first 70% of each fit participant, with its remaining 30% forming the prefix audit/prior. The adapter retains all 12 classes listed in official metadata. Calibration/test labels cannot affect normalization, fitted source models or source-quality priors. The synthetic readiness check verifies this by poisoning both calibration/test features and labels.

The runner exposes `prepared() -> engine,recovery,guard,cfg,service,fork,data,pre`, `verify()`, calibration seeds 122001–122003, and test seeds 123001–123005. Its current scientific binding remains the CJ-R preparation draft, pending the final CJ-T API. Conditional arms use three bandwidths and three q floors; legacy controls use three prior SDs and the same three floors, giving nine configurations each. Every arm uses guarded B130 second-half complete return for selection. All internal/external selections must be locked before testing. No freeze or acquisition command has been executed.

PAMAP2's previous status already documents partial raw acquisition, although no cache/evaluation completed, so it cannot establish acquisition after the next freeze. [OPPORTUNITY](https://archive.ics.uci.edu/dataset/226/opportunity+activity+recognition) and [REALDISP](https://archive.ics.uci.edu/dataset/305/realdisp+activity+recognition+dataset) have larger or less convenient task designs. No alternate raw data were acquired. Metadata for RecGym did not establish cross-location synchronization; it was not used to create row-paired sensor sources.

Ingestion should take several minutes, and calibration/replay may take minutes to tens of minutes depending on actual lengths, run counts and final method integration. No HARTH runtime has been measured. Approximately 1 GB of available storage is a planning estimate for the 296.4 MB archive, compressed cache and results. Full raw extraction is unnecessary because ZIP members are streamed. UCI lists CC BY 4.0, and public access needs no account. A shell download may still require an environment network grant; this preparation does not request or use one.

Portable reproduction must preserve original frozen provenance records separately and regenerate path-bound preparation/freezes in the fresh output project before copying and ingesting the raw archive. In particular, `design/protocol.json` contains absolute source paths; a portable launcher must regenerate or explicitly relocate that metadata, rather than claiming the original records are byte-identical portable bindings. Scientific source files can remain byte-identical because their project roots are computed from file locations. The dependency project hierarchy matches the existing self-contained joint-tail reproduction setup.
